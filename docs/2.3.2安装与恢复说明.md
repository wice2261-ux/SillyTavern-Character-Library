角色库 2.3.2 安装与恢复说明

[下载发布附件](https://github.com/wice2261-ux/SillyTavern-Character-Library/releases/tag/v2.3.2) · [1.1.1 旧版](https://github.com/wice2261-ux/SillyTavern-Character-Library/releases/tag/v1.1.1)

## 前端安装

在酒馆「扩展程序 → 安装扩展程序」填入 `https://github.com/wice2261-ux/SillyTavern-Character-Library`。手动安装时，解压前端 ZIP，把内容放到独立的扩展目录。最终结构如下：

```text
<SillyTavern>/public/scripts/extensions/third-party/character-library/
  manifest.json
  extension/
```

刷新浏览器，展开顶部扩展区的「角色库」。基础模式用户点击「启用自动收回」，核对预览并确认。已有 1.1.1 的账户请先完成下方升级流程。

## 增强后端与接管

1. 停止酒馆并备份账户。解压可选后端 ZIP，保留包内目录结构。
   ```text
   <SillyTavern>/plugins/character-library-enhanced/
     package.json
     server/index.mjs
     extension/
   ```
2. 在酒馆的 `config.yaml` 启用 `enableServerPlugins: true`。Docker 部署应确认当前容器挂载了新的后端目录。
3. 普通账户或已托管的新版基础账户使用 `takeover`。1.1.1 账户走下方 `legacy` 路线。先对独立备份副本预演，核对目标账户后再正式执行。
4. 启动酒馆，刷新前端。检查「运行模式：增强」，打开一张角色卡及其历史。仅检测到后端时，说明账户仍待接管。

## 终端命令和账户路径

在解压后的交接工具目录运行命令。账户路径应直接包含 `characters`、`chats`、`groups` 和 `user` 等目录。例如 Windows 的 `D:/SillyTavern/data/default-user`。多账户按账户分别执行。

Docker 用户可用 `docker inspect <容器名> --format '{{json .Mounts}}'` 查找数据挂载。使用数据卷时，将该卷挂载给能运行交接工具的独立环境，正式写入前保持原酒馆停服。

| 目的 | 预览命令 |
| --- | --- |
| 1.1.1 直接接管 | `node tools/handoff.mjs legacy "<账户目录>"` |
| 普通账户或新版基础模式转增强 | `node tools/handoff.mjs takeover "<账户目录>"` |
| 增强交还基础 | `node tools/handoff.mjs basic "<账户目录>"` |
| 增强恢复原生完整 PNG | `node tools/handoff.mjs restore "<账户目录>"` |

命令默认预览。先对副本预演，完成后检查角色、聊天、群组和所需空间。预览主要检查路径、索引和文件位置。正式交接才会处理并写入卡片。确认原酒馆已停服、正式账户已备份，再把参数换成正式账户目录，在末尾加 `--apply`。例如：

```powershell
node tools/handoff.mjs takeover "D:/SillyTavern/data/default-user"
node tools/handoff.mjs takeover "D:/SillyTavern/data/default-user" --apply
```

这里第二条会写入指定账户。旧版索引导出及 `legacy` 需要支持 `node:sqlite` 的 Node.js，已测版本为 24.15.0。

## 从 1.1.1 升级

### 转增强模式

1. 停服，备份整个账户、旧安装包、配置及适配回滚文件。保留旧的 `character-library/` 目录，包括索引、SQLite 伴随文件及归库数据。
2. 使用新版交接工具，在副本运行 `node tools/handoff.mjs legacy "<副本账户目录>"` 预览，再对同一副本加 `--apply` 演练。正式交接时，对实际账户运行 `node tools/handoff.mjs legacy "<账户目录>" --apply`。
3. 交接成功后，在重启前撤销旧适配、停用旧前后端，再按上文安装新版前端和增强后端。启动后检查模式和原有聊天。
   
这个流程可以直接读取旧版归库文件。

### 转基础模式

1. 先备份。在仍能运行的 1.1.1 中执行旧版恢复全部，确认归库卡已经恢复成完整 PNG。
2. 停服。若要保留旧 ID、收藏和时间，在移走旧数据之前，从新版交接工具目录运行 `node tools/export-v1-metadata.mjs "<账户目录>" "<新输出.json>"`。这个 JSON 只包含索引元数据。
3. 撤销旧适配并停用旧前后端。安装新版前端并启动。若已导出元数据，在设置中先点「导入1.x元数据」，再启用自动收回。

### 撤销旧适配

旧版使用源码适配时，在 **1.1.1 安装包**目录运行 `node adapter/install.mjs revert "<酒馆根目录>"`，保留原来的回滚资料。旧版使用定制 Docker 镜像时，按旧版说明切回原版宿主镜像，并核对旧插件及补丁挂载已移除。重新启动前确认新版使用同一份正式数据挂载。

## 交还、回退与卸载

- **基础模式卸载**：在设置中点「恢复全部并停用自动收回」，确认没有待恢复项，再卸载。
- **增强模式卸载**：点「恢复完整 PNG」。若要继续使用前端管理，可以点「交还基础模式」。后端不可用或交还中断时，停服，用同一目标对应的 `restore` 或 `basic` 离线命令继续。恢复完整 PNG 后，首次打开整库可能再次遇到原生解析峰值。
- **回退到升级前的 1.1.1**：先停服，保留当前数据副本，再成套恢复升级前的账户备份及原有版本的前后端、宿主适配或 Docker 镜像与配置。账户备份对应的时间点之后新增的数据需另行保留。旧安装器的 `revert` 只处理宿主源码。
- **完整备份**：保存整个账户目录。基础模式包含 `user/files/character-library-v2.json` 及其归档。增强模式包含 `user/files/character-library-enhanced.json` 和账户根目录的 `character-library-enhanced/`。「导出恢复资料」只包含目录和引用。确认能重新打开角色和历史后，再清理旧归档。
