# 角色库 2.2.1 安装与恢复说明

首次接管前请备份，在隔离酒馆和数据副本上预演。

## 安装

- 基础模式使用酒馆的扩展安装机制，前端包的根目录包含 `manifest.json` 和 `extension/`。延续 2.1 的归档方式。
- 增强模式另把后端包放入酒馆的 `plugins` 下作为独立目录，在测试宿主的 `config.yaml` 中启用 `enableServerPlugins`，再重启宿主。后端包的 `package.json` 通过 `main` 加载 `server/index.mjs`，也需要包内的 `extension/draw.js` 和 `extension/lifecycle.js`。
- 前端设置显示账户模式、是否检测到后端及协议状态。检测到后端不会自动接管已有账户。Wine Tavern Helper 和其他第三方扩展仍按各自说明安装。

## 交接与交还

停服后备份整个账户目录，包括角色 PNG、`user/files`、聊天、群聊和旧版索引。在数据副本上运行交接工具。命令中的账户目录直接包含 `characters`、`chats`、`groups` 和 `user`。

| 操作 | 命令 |
| --- | --- |
| 预览从 1.1.1 直接接管 | `node tools/handoff.mjs legacy "<账户目录>"` |
| 预览从基础模式接管 | `node tools/handoff.mjs takeover "<账户目录>"` |
| 预览交还基础模式 | `node tools/handoff.mjs basic "<账户目录>"` |
| 预览恢复原生完整 PNG | `node tools/handoff.mjs restore "<账户目录>"` |

核对预览后在同一命令末尾添加 `--apply`。旧索引直接接管需要带内置 SQLite 的 Node.js。增强后端日常运行不读取旧 SQLite。旧库接管完成后，在重启前撤销 1.x 原生适配并停用旧服务端插件。

增强账户也可在设置中预览并确认交还，完成后重载页面。如果在线交还中断，停服后用同一目标模式的离线命令继续。交还基础模式后，打开归库卡仍使用宿主原生解析。恢复完整 PNG 后，首次查看整库可能再次遇到原生解析峰值。卸载前应完成交还，并核对目标模式可以打开角色和历史。

## 文件与兼容性

- 增强目录位于账户 `user/files/character-library-enhanced.json`。正文和原件位于账户 `character-library-enhanced/`。恢复资料只记录引用，备份时应同时保存这些文件。
- 增强后端暂不可用或版本不匹配时，前端会暂停托管角色写入。继续操作前应恢复匹配的后端，或在停服后用离线工具交还。
- 当前验证基线为原版 SillyTavern 1.18.0 和 Node.js 24.15.0。宿主分支及 TauriTavern 的支持以验证记录为准。扩展无法保护绕过当前浏览器入口的第三方直接写盘操作。
