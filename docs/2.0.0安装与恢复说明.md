# 2.0.0 安装与恢复说明

日期：2026-11-16。此交付为本地2.0.0源码与安装包，尚未发布到公开GitHub，也未部署生产或迁移真实角色卡。

## 新用户

公开仓库更新为2.0后，在酒馆「扩展程序 → 安装扩展程序」输入 https://github.com/wice2261-ux/SillyTavern-Character-Library ，刷新即可加载。远端仍为旧版时，输入相同网址仍会安装旧版；本机打包不会自动更新远端。

顶部「角色库」是设置：预览后启用自动收回，查看状态，停止后续迁移或恢复全部。底部魔法棒和右侧书本打开管理弹窗。支持PNG/JSON添加与替换，同名另存为默认；跳过只针对真正重名。批量操作逐项显示成功和失败。

不需要角色库服务端、源码适配器、独立数据库或额外Node版本。Node要求随宿主。Web Locks缺失时使用当前页面保护，仍可自动收回；有能力时增强同源同账户多标签页。跨设备、不同浏览器及未协调页面同时操作不保证一致性。

默认8张未收藏在线卡、192 MiB活动数据估算，均为当前账户管理目标，不是总进程硬限额。收藏、当前单聊/群成员、准备/保存中的卡受保护。有历史聊天不阻止收回；下次使用先恢复。原生列表一直保留轻量卡和原avatar。

单张大卡仍经过宿主解析，首次迁移前的原生整库解析无法追溯消除。迁移逐卡进行，预览使用现有列表轻量投影，不再次取整库正文。文件大小排序使用完整PNG大小，活动估算另用序列化正文大小。

## 从1.1.1升级

1. 保留1.1.1安装包、适配回滚目录和完整账户备份。
2. 在旧版为各账户恢复全部，确认旧归库卡已经交还。
3. 停止旧酒馆，用单独附件导出旧元数据：`node export-v1-metadata.mjs "账户根目录" "新输出.json"`。工具只读旧SQLite、输出新文件；仅这个旧版交接工具需要支持node:sqlite的Node。不得拿当前仍运行的旧收回器与2.0同时接管。
4. 用旧安装器撤销源码适配，停用旧前后端；Docker切到原版镜像并核对真实数据挂载，保管原镜像和回滚目录。
5. 安装2.0，启用前在顶部设置导入旧元数据，再执行迁移。按精确avatar保留可用旧ID、收藏、可靠时间和游玩记录。不支持旧冷态直接迁移，不从前端读取SQLite。

缺失的历史时间保持未知并排后；老卡只用有效带时区ISO create_date补齐，不用文件时间或启用时间。新建/导入/复制采用宿主成功响应Date时间；副本产生新身份和新时间，同卡替换/编辑/往返不重置。若旧版已覆盖历史日期，不承诺恢复丢失信息。

## 备份和恢复

完整备份应包含账户原生角色、聊天、群聊及账户files目录。files中`character-library-v2.json`是目录，`cl2-*`是原件及正文版本。仅导出原生列表的占位PNG不能备份全文。

「导出恢复资料」导出目录与文件清单，不打包全部正文，须与账户files备份配合。目录丢失时，可在停服和完整备份后，从导出的恢复资料提取`directory`对象，保存为账户files下`character-library-v2.json`，并一并交还清单所列文件，再启动2.0执行恢复；不要把整个导出包装对象当作目录文件。

启动恢复逐项核对未完成阶段。完整在线卡可能包含更新的编辑，优先保护它；迁移原始PNG不是编辑后正文的权威来源。冲突保留双方，单卡失败不阻断其他卡；处理后可继续恢复。

## 停用、卸载与回退

先点击「恢复全部并停用自动收回」，确认剩余占位为0、恢复状态结束，再禁用或卸载。直接删除前端不会自动恢复全文。恢复后的原生PNG保留无害身份扩展标记，但已经是完整卡，普通酒馆可读取。

恢复后原生整库内存开销会回升。保留最后可用副本和完整备份前，不清理账户归档文件。若重新启用1.x，也应先完成2.0恢复，再按旧版说明安装，不能共用两套目录和收回器。

2.0未构建自定义Docker镜像，测试实际运行原版1.18.0镜像加前端扩展；Docker用户同样通过酒馆界面安装。
