# 角色库 2.3.0 验证记录

受测基线为原版 SillyTavern 1.18.0、Node.js 24.15.0，以及隔离 Chrome 中的酒馆助手 4.12.0。浏览器操作由 GPT-6.1-TERRA-MEDIUM 执行。VPS 使用隔离 Docker 容器，备份以只读方式挂载，测试写入容器副本。

| 验证 | 结果 |
| --- | --- |
| 基础抽卡 | Chrome 中使用 12 张合成卡，抽卡和重抽各返回 3 张，返回后恢复 12 张。抽取和返回期间没有角色正文请求。Node 测试以 3,003 条轻量记录验证跨页、有重复输入、不足和空结果。 |
| 增强浏览器 | 合成卡冷开成功，原生编辑后重开保留修改和历史指针，JSON／PNG 导出成功，原生目录仍是 v3 占位。单次表单操作观察到两次保存请求，均成功。 |
| 群聊与异常 | 两张冷卡在群聊打开前加载，按各自角色显示开场白。后端断开时，进入群聊被停止。原生改名同步群成员引用。协议不匹配由 Node 夹具验证。 |
| 收回与助手 | 11 张卡切换后收回到 8 张。代表卡页面对象确实变为占位，重开后读到了同一变量，脚本重新启动，原授权仍在。增强抽卡只请求抽样接口，选中冷卡后才请求正文。 |
| 最大真实卡 | 源 PNG 为 40,685,773 字节。隔离宿主 HTTP 验证打开、保存、重开、复制及 JSON／PNG 导出。原生占位为 665,320 字节，正文版本约 14.3 MiB。 |
| 416 张真实库 | 定向读取通过 416 张。1.1.1 备份直接交接后原版宿主首次启动，原生列表及增强目录均有 416 张。另一次演练在归档日志提交后强制中止，续跑后实际交还基础模式。全部 416 张核对了身份、收藏、时间、占位和归档引用，聊天及群组文件哈希一致。 |
| Windows 文件层及回退 | 原版加载器挂载后端成功。合成旧冷卡续跑、基础冷卡再接管、增强回基础及离线恢复完整 PNG 通过。名称大小写冲突保持保护，改名保留聊天文件。 |
| 源码测试 | 67 项 Node 测试通过，包含暂停或冲突时保护数据、增强角色保存版本检查、PNG 替换及恢复。 |

## 资源观测

- 单张最大卡 HTTP 试验中，酒馆进程按 100 毫秒采样的最高 V8 已用堆约 232 MiB，最高 RSS 约 386 MiB。容器计数峰值约 619 MiB，包含测试客户端、宿主启动和文件缓存。
- 416 张库的交接和启动在 768 MiB 限额完成，容器计数峰值达到限额。该数值覆盖交接及启动全程。浏览器最高堆未单独测量。

## 兼容性边界

| 宿主与环境 | 结论 |
| --- | --- |
| 原版 1.18.0，Windows，Chrome | 基础及增强代表流程已实测。 |
| 原版 1.18.0，Linux Docker | 增强启动、真实大卡 HTTP 及账户交接已实测。 |
| 其他版本具备同等原生接口的宿主 | 以实际能力检查为准，未做全流程实测。 |
| TauriTavern、移动设备及其他分支 | 两种模式均未实测。缺少宿主服务端插件机制的环境无法使用增强后端。 |

增强管理导入支持 PNG／JSON，删除角色保留单聊。批量属性、头像和原生导入／新建已接入，实际浏览器覆盖以表内项目为准。未知第三方入口仍可能绕开准备。416 张实库样本没有冷卡，旧冷卡覆盖来自合成夹具。真实整库交还基础模式已验证，恢复完整 PNG 以合成夹具覆盖。两种恢复路径都应在部署前保留账户备份。
