# SillyTavern 低内存角色库

插件版本 **1.1.1**。将闲置角色卡归库，浏览轻量索引，打开单聊或群聊时按需载入。支持添加、删除、收藏、搜索和排序，聊天、变量、世界书与助手脚本继续由酒馆使用。

仓库地址：<https://github.com/wice2261-ux/SillyTavern-Character-Library>

相关文档：[验证记录](./验证记录.md)（本轮测试范围、已覆盖与未覆盖项）、[发行说明](./RELEASE_NOTES.md)、[第三方许可](./THIRD_PARTY_NOTICES.md)、[MIT LICENSE](./LICENSE)。

## 版本与兼容性

受测基线是 **SillyTavern 1.18.0、Node.js 24.15.0、酒馆助手 4.12.0**。插件版本不是 1.18.0；发布标题应写为“角色库 v1.1.1（受测 SillyTavern 1.18.0）”。内部适配协议中的历史标识也不是插件版本。

其他酒馆版本不保证兼容，但不会仅因版本号不同而直接拒绝。安装前运行 `check`：已知原件指纹用于快速确认，其他源码通过各适配目标的唯一锚点和转换检查。目标不存在、结构不匹配或有无法识别的修改时停止，不盲目写补丁。原件备份、安装后修改检测和逐字节回退继续保留。

酒馆升级可能改变这些结构，因此每次升级应先恢复旧适配、保管回滚目录，再对新源码重新检查。`check` 通过只表示可应用当前转换，不等于已完成其他版本的运行兼容验证。第三方 PNG 解码依赖仍按已知原件指纹检查，避免覆盖未知实现。

## 安装

推荐使用 Release 的完整 ZIP，先备份整个酒馆账户和配置，再停止酒馆。

1. 把包内 `server` 目录的内容复制到酒馆 `plugins/character-library`，把 `extension` 目录内容复制到 `public/scripts/extensions/third-party/character-library`。
2. 在完整包目录执行（替换最后的酒馆根路径）：

   ```sh
   node adapter/install.mjs check /path/to/SillyTavern
   node adapter/install.mjs apply /path/to/SillyTavern
   ```

3. 配置 `enableServerPlugins: true`，启动并刷新所有使用窗口。顶部扩展设置展开“角色库”；底部魔法棒菜单或右侧书本按钮打开角色库管理。

### 通过 GitHub Install Extension 安装前端

仓库根目录提供 `manifest.json`，入口为 `extension/index.js` 和 `extension/style.css`。酒馆 Install Extension 会克隆**整个仓库**，不是只下载 `extension/`。这仅完成前端安装，仍须由服务器操作者安装服务端和运行适配安装器；只装前端不能完成归库功能。

填法：酒馆「扩展（Extensions）」→「安装扩展（Install Extension）」，URL 填

```
https://github.com/wice2261-ux/SillyTavern-Character-Library
```

确认后刷新页面。等价的手工方式是在服务器执行 `git clone https://github.com/wice2261-ux/SillyTavern-Character-Library`，放到 `public/scripts/extensions/third-party/` 下，目录名保持 `SillyTavern-Character-Library`。

安装后在浏览器 `F12` → 网络面板应看到三条 200：`third-party/SillyTavern-Character-Library/extension/index.js`、同目录 `extension/style.css`，以及仓库根 `manifest.json`。`extension/index.js` 首行 `import * as native from '../../../../script.js';` 依赖扩展目录正好位于 `public/scripts/extensions/third-party/<目录名>/extension/` 的深度，手工放置时不要压平这一层。

整仓克隆会把 `server/`、`test/`、`adapter/` 等源码也放到酒馆前端扩展目录，这些文件可能直接通过 HTTP 访问。源码本身公开，但不要在仓库或该目录中存放密钥、用户数据和本地备份。本轮不拆分前端仓库。

### 升级与回退

使用当前已安装版本的旧安装器先执行 `revert`，将旧 `.st-character-library-adapter-1.18.0` 目录改名保管，然后更新配套前后端，再用新安装器 `check` 和 `apply`。该回滚目录名沿用历史名称，并不表示插件版本，也不要手工混合不同包的适配文件。

回退时先停服，用当前包回退适配，再还原对应旧前后端及旧回滚目录。适配回退只恢复程序文件，不撤销角色、聊天或索引变更。恢复未完成的账户先完成恢复再切旧版。

### Docker

完整包提供 Dockerfile，可构建独立镜像标签，例如 `sillytavern-character-library:1.1.1`。其基础镜像仍使用受测酒馆版本；希望使用其他版本时应自行调整基础镜像并验证。不要覆盖旧镜像标签；宿主机插件挂载会遮住镜像中的插件，须同步更新对应挂载内容。运行配置和端口沿用原 Compose 设置。具体是否实际构建测试见 [验证记录](./验证记录.md)。

## 使用

顶部设置管理自动收回的启用预览、恢复全部及部分恢复重试，并只读展示实际资源预算；日常添加、删除、收藏、搜索、排序在魔法棒打开的角色库中操作。首次启用会整理闲置卡，收藏及使用中的卡保留。

同名处理按**实际目标文件名**匹配，不按角色显示名匹配：

- **同名另存（默认）**：使用新文件名和新身份，独立授权助手脚本。
- **同名跳过**：只跳过明确的文件名占用错误，其他失败显示真实原因。
- **同名替换**：更新同一张卡，保留身份、聊天历史及原导入时间；先退出所有正在使用该卡的窗口。冷卡和在线卡均受身份、文件冲突与占用检查保护，失败保留原文件。已有角色的助手授权沿用原身份。

库内同名替换更新主卡并保留原收藏；卡内嵌入数据保留，但不额外展开本次替换中新带的 Risu 立绘文件，已有立绘目录保持。

删除默认保留单聊，删除聊天需另行勾选。被删除或改名的旧文件名可继续保留占用，不能把这种占用当成可替换的实际卡片。群聊成员必须能唯一解析；准备失败时保留原聊天。

## 导入时间与旧索引升级

新卡成功加入当前账户时记录服务端时间，涵盖原生创建、导入、复制和角色库添加。首次在线、启用插件、归库、重载、编辑、收藏、改名和同卡替换均不重置已记录时间；复制为新卡，使用新时间。

升级会串行补齐旧索引。已有有效时间保留，空值从卡片顶层带时区的有效 ISO `create_date` 补齐。没有可用记录的老卡显示未知，不使用文件创建／修改时间或插件启用时间估算。不带时区的原生历史格式也归为未知；被旧操作覆盖的日期无法还原，完全丢失索引时只能恢复卡片中仍保留的日期。

升级在 SQLite cards 表追加内部 `imported_checked` 整数检查点，并使用账户 settings 版本标记完成整轮升级。该检查点使一张坏卡导致升级未完成时，已处理的未知时间不会在重启或重试中变成后来的编辑时间。它不修改旧 PNG 或聊天，不改变稳定 ID；请像以往一样备份完整账户目录，包含索引及其 WAL 文件。单卡错误显示在索引进度中，处理后可继续。

## 资源设置

服务端共用一个解析队列，一次处理一项，至多接收 32 项。缩略图按需生成，保留最近使用的最多 96 个生成结果，单张上传上限为 64 MiB。程序根据单卡解析文本长度估算活动数据，实际堆和 RSS 还受原生代码、助手与卡内脚本影响。

同一时间接收一张上传卡。慢速上传期间其他窗口仍可选卡、保存和续期，第二项上传会提示稍后重试。旧版显示名群成员必须能在账户中唯一定位；出现重名时请核对该群的成员，直接使用各自的头像文件名。

托管角色的编辑及单聊保存会校验打开时绑定的身份。恢复全部后，已经携带 ID 的请求仍校验原身份，既有保留名继续有效；旧窗口不能借恢复完成或强制保存重建旧路径。自行构造托管写请求的第三方扩展须携带目标卡的身份；使用旧窗口凭据跨角色写入会收到 HTTP 409。需要保存成功才能继续的单聊历史、分支、书签和替换入口会在网络错误、服务器拒绝或等待超时后停止，保留当前会话和输入。副本已保存而原聊天关联失败时，会说明部分完成并保留副本。严格保存中完整性校验未确认覆盖时同样停止，不强制刷新页面；普通后台保存保留原有行为。

| 设置 | 默认值 | 含义 |
| --- | ---: | --- |
| `ST_LIBRARY_ONLINE` | 8 | 所有已托管账户共用的未收藏常驻数，切换时允许暂多 1 张 |
| `ST_LIBRARY_BUDGET_MIB` | 192 | 活动数据估算预算，扣除酒馆配置的原生缓存容量和 24 MiB 切换预留 |

顶部设置只读展示服务端实际生效的常驻数量和活动数据估算预算。它们由全部托管账户共用，预算含原生缓存与切换预留，不是浏览器或容器内存硬上限。环境变量在启动酒馆前设置。收藏和正在使用的群成员也占预算；若它们占满容量，打开新角色会提示释放占用。每个账户的 `character-library/index.sqlite` 保存轻量字段，`character-library/cards` 保存归库 PNG。它们必须与该账户的 `characters` 位于支持硬链接的同一文件系统。备份时应包含整个账户目录。

## 恢复和卸载

1. 正常运行时先在顶部扩展设置的「角色库」执行恢复全部。遇到单卡冲突，页面列出待处理文件，其他已恢复卡保持在线。此时可以继续使用已交还的卡，暂停新导入和冷卡打开。先备份冲突双方，核对内容并处理后重试；重启也能继续。确认全部交还并停用托管后再卸载。恢复到全部在线后，原生角色列表的扫描和内存开销也会增加。
2. 恢复完成后停服。源码版执行 `node adapter/install.mjs revert /path/to/SillyTavern`，原始文件取自该酒馆根目录的 `.st-character-library-adapter-1.18.0`。Docker 版切回原镜像与原挂载。移出本插件的前后端目录后启动酒馆。
3. **酒馆或插件启动不了时**，停服，用安装包中的恢复工具处理单个账户。先预览，再应用。工具可在索引损坏时运行；遇到同名冲突会保留双方并报告，退出码为 2。离线恢复后先按上一步禁用插件及适配，再启动原版酒馆。

   ```sh
   node recover.mjs /path/to/SillyTavern/data/default-user
   node recover.mjs /path/to/SillyTavern/data/default-user --apply
   ```

   Docker 镜像内的恢复工具为 `/opt/st-character-library/recover.mjs`，索引修复工具为 `/opt/st-character-library/repair-index.mjs`。使用一次性工具容器时先停酒馆服务，继续挂载同一份账户数据，并把命令中的账户目录替换为容器内的实际挂载路径；不要用未挂载数据的新容器执行恢复。

## 大小写双 ID 的离线索引修复

此工具仅处理一个实际 PNG 在普通大小写不敏感 Windows 目录中对应两条索引的情况。先停服并备份整个账户，在该 Windows 环境使用 Node.js 24.15.0 和解压后的完整安装包操作。`--avatar` 必须使用磁盘实际拼写；默认只预览：

```sh
node repair-index.mjs "/path/to/account" --avatar "Alice.png"
```

预览列出两条原索引及 ID。核对后明确选择要保留的旧 ID，再应用：

```sh
node repair-index.mjs "/path/to/account" --avatar "Alice.png" --keep-id "要保留的旧ID" --apply
```

应用前，工具将受影响记录导出到该账户 `character-library/index-repair-*.json`，返回结果中的 `backup` 为实际路径。随后在同一 SQLite 事务中保留所选 ID、对齐实际文件名并移除另一条索引；不修改 PNG 或聊天。存在未完成移动、多个物理文件或其他不符合条件的状态时会拒绝，保留现状；冲突退出码为 2，参数或运行错误为 1。

修复后启动酒馆并重新打开该角色，旧的另一个 ID 将失效。工具不会代选历史身份，也不合并 Linux 上两个真实存在的大小写不同文件。若索引不可读或需要先交还物理文件，使用上节 `recover.mjs`，不要把索引裁决混入普通恢复。
