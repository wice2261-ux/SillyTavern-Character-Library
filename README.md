# SillyTavern 低内存角色库

角色库提供基础和增强两种模式。两种模式都让闲置角色保留头像和轻量占位，正文在需要时读取。聊天、群聊和其他资源仍由酒馆原生管理。

## 安装与使用

发布分支更新后，在酒馆顶部「扩展程序 → 安装扩展程序」输入下面的地址。

```
https://github.com/wice2261-ux/SillyTavern-Character-Library
```

刷新页面，在顶部「角色库」展开设置。基础模式可以直接预览并启用自动收回。增强模式需要单独安装可选服务端包，再按安装说明接管账户。两种模式都无需修改酒馆源码，Node.js 要求遵循宿主。

底部魔法棒菜单或右侧书本打开同一管理界面。支持添加、删除、收藏、搜索、分页、批量操作，以及名称、导入酒馆时间、游玩时间、大小排序。添加默认同名另存，也可跳过或替换；只按实际文件名判断同名。未知导入时间排后，不用插件启用时间替代。

抽卡默认抽取 3 张，可选 1–12 张。按当前搜索条件从全部匹配角色中抽取，搜索为空时覆盖全库。同一轮不重复，重抽允许抽到上一轮的角色。抽卡只读取索引，选中角色后才准备正文。

## 2.1可选世界书

顶部设置提供「自动更新专用世界书」，默认关闭；关闭时仍可点击「手动更新世界书」。首次手动更新创建资料副本，不打开自动开关。开启后，添加、删除、改名、标签和收藏等管理操作合并触发更新；切卡、收回和游玩时间变化不单独触发，时间资料在下一次更新时顺带刷新。

自动更新开启时，每次页面管理就绪会核对一次轻量资料，补上刷新前遗漏的更新；关闭时不发起启动核对。无关标签的颜色、文件夹或群聊关联变化不触发资料更新。核对失败只显示世界书错误，不阻塞角色管理，也不周期重试。

世界书只包含ID、文件名、名称、标签、收藏及时间，不含角色正文、脚本或聊天，也不能用来恢复全文。生成条目默认禁用且不自动绑定；用户自行绑定、启用后可能进入提示词。手动修改的生成条目会在下次更新时被覆盖。

世界书有额外的轻量序列化与宿主解析开销。首次创建或碰到空书时，为区分同名用户书与缺失文件，原生列表可能读取其他世界书；正常非空资料更新不需要整库列表。更新失败只在专用状态中显示，不影响已成功的角色操作；可手动重试。关闭或卸载不删除已有资料书，可通过原生界面自行删除。

2.1保留2.0目录和正文格式，升级不需要恢复全库；主要存储优化是避免无任务恢复及清理失败时的无变化目录提交，不省略关键恢复阶段。恢复资料导出追加文件角色和引用关系，不下载正文。

## 内存管理

默认目标为8张在线卡（含收藏）、192 MiB活动数据估算。收藏默认仅高亮、可置顶，与普通卡按同一规则收回。有历史聊天的角色仍可收回，下次使用前恢复。当前单聊和群成员、准备中及保存中的角色继续受到保护。

设置页「保持收藏卡加载」默认关闭，旧账户升级缺少此设置时也关闭。开启后，已加载收藏卡免于自动收回且不计入8张普通在线目标；归库收藏卡不批量预载，使用恢复后保持在线。收藏卡仍计入活动数据估算，受保护对象可能使实际在线量超过目标。关闭开关会安排一次正常收回检查，不强行卸载当前会话。

基础模式在打开归库卡时会将完整 PNG 交给宿主解析。首次迁移前，宿主也可能已读取原有整库。增强模式可停服后先接管账户，使宿主首次启动只看到占位。打开增强角色时，经后端读取正文，磁盘继续保留占位，闲置后释放浏览器中的完整对象。

管理目标只估算该账户的活动正文。单张大卡、头像、原生缓存、其他账户及同机服务都可能增加内存开销。基础模式迁移逐卡执行，可以停止后续处理。

## 浏览器与兼容

Web Locks可用时自动增强同来源、同账户标签页协调；不可用时仍提供当前页面保护和自动收回。不保证跨设备、不同浏览器或未协调页面的并发一致性。

首个验证基线为SillyTavern 1.18.0、Node.js 24.15.0、酒馆助手4.12.0。其他版本按所需接口和入口判断，不按版本字符串硬拒绝；尚未承诺TauriTavern兼容。实际测试结果见随包验证记录。

前端只能保护已接管的操作，不能对外部HTTP客户端强制身份校验。未覆盖的第三方入口可能绕过准备流程。具体冲突限制对应操作，不据此全局禁止未知扩展。

## 备份、恢复与卸载

**卸载之前先恢复完整 PNG，确认没有剩余占位或失败项。** 增强模式也可先交还基础模式，保留前端继续管理，再按基础模式流程恢复。

账户备份应包含角色、聊天、群聊及`user/files`中的`character-library-v2.json`与其引用的`cl2-*`文件。仅导出角色列表里的占位PNG不能恢复全文。设置的恢复资料导出提供目录、文件名清单和说明，不包含全部正文；它须与账户文件备份配合使用。

增强账户还需备份 `user/files/character-library-enhanced.json` 及账户根目录的 `character-library-enhanced/`。后端不可用时可在停服后使用离线交还工具。

最新完整在线卡优先于旧归档；迁移原始PNG仅供原件对照，不能覆盖后续编辑。恢复逐卡进行，失败项处理后可继续，其余卡不受影响。保留最后可用副本后再处理冲突。

## 从1.1.1升级

增强模式支持停服后直接交接 1.1.1 账户，读取旧索引和在线／归库文件，无需先将整库恢复为完整 PNG。先备份并在数据副本上预览。完成交接后，在启动前撤销旧角色库适配并停用旧后端。基础模式仍可使用旧版元数据导出工具按精确文件名交接。
